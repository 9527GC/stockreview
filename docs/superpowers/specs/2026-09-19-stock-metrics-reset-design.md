# 股票复盘指标统一与账户重置设计

**日期：** 2026-09-19  
**状态：** 已确认，待实施  
**范围：** 后端指标模型、用户数据重置、前端指标展示适配与自动化测试。

## 目标

将账户资产、资金流、持仓估值、日收益、收益曲线、收益日历和已清仓历史统一到同一套可追溯的计算口径；清空所有现有用户业务数据，保留账号身份与登录绑定，使新版本从零开始累计数据。

## 非目标

- 不迁移、修复或展示旧交易、旧复盘、旧资产和旧收益数据。
- 不保留旧摊薄成本结果作为历史兼容口径。
- 不改变用户的登录身份、密码哈希、微信绑定、头像昵称等身份资料。
- 不删除系统级行情缓存、股票代码库和非用户维度的市场快照。

## 数据重置

### 清除范围

对每个用户删除下列用户业务数据：

- `Trade`：交易及其复盘字段。
- `Holding`：当前持仓。
- `Transfer`：转入与转出。
- `Asset`：资产汇总。
- `DailyProfit`：日收益和累计收益。
- `DailyRevenue`：收益日历数据。
- `MonthlyStats`：月度统计。
- 任何由上述数据生成的用户维度脏数据或快照。

### 保留范围

- `User` 身份、登录凭证、微信绑定、头像和昵称。
- 系统级 `HistoricalQuote`、市场快照和股票代码数据。
- 手续费偏好恢复为服务端默认值，而非沿用旧用户设置。

### 执行方式

提供仅管理员/运维可执行的重置脚本。脚本默认要求显式确认标志，支持指定用户与全用户两种模式；删除完成后打印各集合的删除数量。重置操作幂等：重复执行后账户仍为无业务数据的初始状态。

## 统一数据模型

### 原始流水

每笔 `Transfer` 必须持久化不可变换算信息：

- `amount`：原始金额；
- `currency`：原始币种；
- `fxRateToCNY`：创建时一单位原始币种对应的 CNY；
- `amountCNY`：`amount * fxRateToCNY`，按两位小数保存；
- `date`：精确 UTC 时间戳，但归属业务日始终用北京时间计算。

每笔 `Trade` 必须使用标的市场唯一确定的交易币种，并持久化：

- `currency`；
- `fxRateToCNY`：交易创建时的汇率；
- `grossAmount`、`commission`、`netSettlementAmount`：均为原始币种。

交易的原始清算金额不得在后续账本重建时因当前汇率而变化。

### 资金账户

账户现金采用按币种余额的账本，而不是单一 CNY 现金字段：

```js
{
  CNY: Number,
  HKD: Number,
  USD: Number
}
```

- 入金/出金只变动其原始币种现金余额。
- 买入减少、卖出增加标的币种现金余额。
- 当前 CNY 现金估值由余额乘当前汇率计算。
- `Asset.cash` 保留为当前全部现金的 CNY 估值，供现有展示接口兼容。
- `Asset.currentPrincipal` 为入金减出金的锁定 CNY 金额之和，不因未来汇率变化重算。

### 持仓

每个未清仓标的持有固定的市场与币种。市场币种映射为：

- A 股：`CNY`；
- 港股：`HKD`；
- 美股：`USD`。

后端拒绝与标的市场不一致的币种；同一未清仓标的也不得修改币种。

## 估值与指标定义

### 唯一估值引擎

新增集中式估值模块，输入资金账户、持仓、行情、汇率，输出：

```js
{
  cashByCurrency,
  cashCNY,
  holdingsMarketValueCNY,
  totalAssetsCNY,
  valuations: [{ symbol, price, priceDate, source, isStale }],
  quality: 'complete' | 'partial' | 'stale'
}
```

首页资产汇总、资产刷新、今日盈亏、日收益快照、收益日历和收益曲线只能消费该模块或其生成的日快照；不得各自重新实现估值计算。

### 行情缺失

单个持仓估值价格优先级：

1. 当前有效实时价或当日收盘价；
2. 最近一个有效收盘价；
3. 无任何有效价格时，标的估值为 `null`，总体快照标记 `partial`。

严禁以持仓成本作为行情缺失时的价格。使用最近有效价格时，记录该价格日期并标记 `stale`。

### 日盈亏金额

```text
日投资盈亏 = 当日估值总资产 - 昨日收盘总资产 - 当日外部净资金流（CNY）
```

买卖成交属于内部资产转换，不能计入外部资金流。外部资金流使用转账落库时锁定的 `amountCNY`。

### 日收益率

日收益采用 Modified Dietz：

```text
日收益率 = 日投资盈亏
          /（昨日收盘总资产 + Σ 外部现金流 × 日内剩余时间权重）
```

每笔资金流的权重为该笔发生时间距当日结束的分钟数除以全天分钟数，限定在 `[0, 1]`。当日无起始资产且无有效分母时，日收益率为 `0`，不以无限大或空值表示。

### 累计收益和曲线

收益曲线使用日收益率复利，而非账户资产比值：

```text
累计收益率 = Π(1 + 每日收益率) - 1
```

因此，入金、出金改变账户规模但不改变投资收益曲线。累计盈亏金额仍定义为：

```text
累计盈亏金额 = 当前总资产 CNY - 锁定本金 CNY
```

该金额包含外币现金和外币持仓因汇率变化产生的汇兑盈亏。

## 成本与已清仓历史

### 标准口径

当前持仓主展示采用加权平均成本：

- 买入：成本增加 `成交金额 + 手续费`；
- 卖出：按当前加权平均成本结转已卖出成本；
- 未实现盈亏：市值减剩余成本；
- 已实现盈亏：卖出净收入减结转成本。

已清仓历史按完整持仓周期拆分：从持仓数量由零变为正开始，到数量再次归零结束。每个周期独立返回成本、卖出净收入、已实现盈亏、收益率、交易笔数和币种/CNY 换算金额。

### 摊薄成本法

保留摊薄成本法，但仅作为当前持仓的可选展示指标：

- 不作为资产账本、日收益、累计收益或已清仓周期收益的底层口径；
- 单独返回 `dilutedAvgCost`、`dilutedUnrealizedProfit` 等字段；
- 不能与标准已实现盈亏混合成同一字段。

## 日期、时间和边界

所有用户业务日统一使用北京时间（UTC+08:00）：

- 交易和转账所属日期；
- 收益快照的 `date`；
- 收益曲线的筛选区间；
- 收益日历的月份边界；
- 脏数据起点；
- 调度任务的执行判断。

业务代码不得使用 `new Date().toISOString().slice(0, 10)` 推导用户业务日期，必须使用统一日期工具。UTC 时间戳仅用于存储精确发生时刻与时间排序。

## 接口行为

- `GET /api/assets/summary`：从唯一估值引擎读取当前资产与今日盈亏；返回数据质量状态。
- `GET /api/assets/profit-calendar`：读取统一生成的每日快照；金额和收益率与曲线一致。
- `GET /api/assets/profit-curve`：将所选日期范围内的日收益率复利；不直接比较总资产。
- 当前持仓接口：默认返回加权平均成本指标，同时返回可选摊薄成本指标。
- 已清仓历史接口：每个完整持仓周期一条记录，而非按股票代码跨周期聚合。

## 一致性不变量

1. `totalAssetsCNY = cashCNY + holdingsMarketValueCNY`。
2. 所有首页、快照、日历和曲线接口对同一个快照日期使用相同的日盈亏金额。
3. 转账不改变同一时点的投资收益；只改变本金和账户规模。
4. 同一天无交易、无转账且全部价格/汇率不变时，日盈亏为零。
5. 同一完整持仓周期的收益率分子和分母必须来自同一周期。
6. 历史流水 CNY 换算值在创建后不可因当前汇率变化而改变。
7. 日期筛选在北京时间 00:00 至 23:59:59.999 范围内一致。

## 验收测试

- 初始入金、追加入金、出金不会造成曲线虚假跳涨或跳跌。
- 不同日内时刻的入金符合 Modified Dietz 权重。
- A 股、港股、美股、外币现金的总资产与币种余额一致。
- 当前汇率变动只影响当前估值与汇兑盈亏，不改写历史转账/成交金额。
- 当日买入、卖出与清仓后的首页今日盈亏、日历金额、日快照金额一致。
- 同一标的两轮完整清仓周期产生两条历史记录，收益率互不污染。
- 行情缺失时使用最近有效价格并标记质量，不使用成本价。
- 北京时间跨日、月初、年初的查询范围正确。
- 重置脚本执行后用户仍可登录，但所有业务数据为空；重复执行仍成功。
