# 股票交易复盘系统（Stock Review）PRD

## 1. 背景与目标

### 1.1 背景

投资者在实际交易中往往缺少结构化复盘：交易原因、执行质量、情绪状态、市场环境与后续改进难以沉淀，导致重复犯错。本产品提供“交易记录 + 结构化复盘 + 资产与收益可视化 + 多市场多币种支持”的一体化工具，帮助用户提升交易纪律与复盘效率。

### 1.2 产品目标

- 让用户能够快速记录每一笔交易，并沉淀完整复盘信息。
- 提供清晰的资产、收益、持仓盈亏展示，支撑复盘决策。
- 支持 A 股 / 港股 / 美股、多币种持仓展示。
- 通过收益曲线、收益日历等图表形成可视化反馈闭环。

### 1.3 成功指标（建议）

- 交易记录完成率：创建交易后填写复盘字段的比例。
- 复盘覆盖率：近30天有复盘的交易占比。
- 日活/周活：打开资产页、复盘列表页的活跃用户数。
- 数据准确性投诉率：价格/盈亏异常反馈数量。

***

## 2. 用户与使用场景

### 2.1 目标用户

- 个人投资者（中短线、波段、价值投资者）
- 对交易纪律与复盘有需求的进阶用户
- 多市场投资者（A/H/US）

### 2.2 核心场景

1. **盘中/盘后快速记账**：交易完成后立即添加交易，自动填入最新价并补齐交易细节。
2. **周末复盘**：查看复盘列表，对交易执行与心态进行归因总结。
3. **资产跟踪**：随时查看总资产、现金、持仓市值、累计盈亏与当日盈亏。
4. **收益复盘**：通过收益曲线/收益日历回看关键波动日期，并关联当日交易。

## 5. 功能需求（PRD详细）

### 5.1 登录与鉴权

**目标**：保证所有需要数据的接口均在登录状态下访问

- 用户输入账号/密码登录
- 登录成功后保存 token（Bearer Token）
- 请求拦截器自动携带 Authorization
- token 失效时自动提示重新登录

**异常要求**

- 未登录访问行情/持仓接口应返回 401 并前端提示“请先登录”

***

### 5.2 交易管理（新增交易）

**目标**：快速记账 + 自动带出市场与最新价 + 支持复盘字段

**字段（核心）**

- 股票代码/名称（可搜索）
- 市场：A股/CN、港股/HK、美股/US（自动识别）
- 方向：BUY/SELL
- 成交价格（默认自动填充最新价，可手改）
- 成交数量
- 手续费率（‱）
- 交易时间（含时分秒）
- 复盘字段：个人状态（心态）、交易逻辑、（可扩展：系统符合度/认知偏差/改进措施等）

**自动填充逻辑**

- 当用户在下拉中选中个股或输入股票代码后：
  - 调用 `GET /api/market/quote?symbol=xxx`
  - 将返回的 `price` 填入“成交价格”作为默认值
- 盘后/停牌：
  - 接口应返回当日最新可用价格（如收盘价）

**保存逻辑**

- 保存交易后刷新持仓与资产概览

***

### 5.3 资产与持仓

**目标**：提供清晰可信的资产结构与盈亏情况，支持多市场多币种展示

**资产指标**

- 总资产（统一折算 CNY，由后端计算）
- 当前现金/可用资金
- 持仓市值
- 累计盈亏（已实现+未实现）
- 今日盈亏（来自后端持仓接口）

**持仓列表字段（建议与现有接近）**

- 股票（名称/代码/市场标签）
- 现价 / 成本价
- 持仓数量
- 市值（原币种）
- 累计收益率（%）
- 今日盈亏（原币种）
- 币种显示：根据 currency 展示 ¥ / HK$ / $

***

### 5.4 复盘管理

**目标**：形成可检索、可统计的复盘记录库

**复盘列表页**

- 列表展示：时间、股票、买卖方向、价格、数量、复盘结果摘要等
- 操作：
  - 打开复盘编辑弹窗（ReviewModal）
  - 删除单条复盘/交易记录

**复盘编辑**

- 修改并保存复盘字段
- 保存后更新列表并提示成功

***

### 5.5 历史持仓明细

**目标**：按股票查看历史交易流水，支撑复盘追溯

**功能**

- 展示该股票历史交易列表（时间、方向、价格、数量、金额、手续费、交易逻辑等）
- 删除能力：
  - 删除单笔交易
  - 删除该股票全部历史记录（高风险操作，需二次确认）

***

### 5.6 图表分析

**目标**：用图表强化复盘反馈

1. **收益曲线**
   - 展示账户收益曲线
   - 对比大盘基准（若后端提供 benchmark）
   - 支持时间维度切换：日、周、月、季、年、全部
2. **收益日历**
   - 展示每日盈亏
   - 支持月胜率、盈亏分布等统计（如已有）

### 5.6.1 收益曲线与上证指数数据存储

#### 数据存储

| 数据类型 | 存储内容 | 更新时机 |
|----------|----------|----------|
| 历史收益曲线 | 日期、累计收益率、当日收益率 | 凌晨定时任务（T-1及之前） |
| 历史上证指数 | 日期、指数值、涨跌幅 | 凌晨定时任务（T-1及之前） |
| 历史营收金额 | 日期、营收金额、累计营收 | 凌晨定时任务（T-1及之前） |
| 营收日历 | 每日盈亏金额、累计盈亏 | 凌晨定时任务（T-1及之前） |
| 月度统计 | 盈利天数、亏损天数、胜率、月度总盈亏、月度总收益率 | 每月初计算 |
| 月度/年度快照 | 月初资产、累计收益、收益率 | 每月/每年初 |

#### 实时计算（当天）

```
查询请求（range=day/today）：
  ↓
返回实时计算结果（不存入数据库）
  - 当日收益率 = (当前总资产 - 昨日收盘总资产) / 昨日收盘总资产
  - 当日盈亏金额 = 当前总资产 - 昨日收盘总资产
  - 上证指数当日涨跌幅 = (当前指数 - 昨日收盘指数) / 昨日收盘指数
```

#### 时间维度

| 维度 | 数据来源 |
|------|----------|
| 日 | 实时计算（当天）+ 缓存（历史） |
| 周 | 缓存（历史）+ 实时计算（本周） |
| 月 | 缓存（历史）+ 实时计算（本月） |
| 季 | 缓存（历史）+ 实时计算（本季） |
| 年 | 缓存（历史）+ 实时计算（本年） |
| 全部 | 缓存（历史）+ 实时计算（成立以来） |

#### 合并逻辑

```javascript
// 示例：获取月度数据
function getProfitCurve(range = 'month') {
  // 1. 获取历史缓存数据（上月及之前）
  const cachedData = queryCache(range);
  
  // 2. 获取实时数据（本月）
  const realtimeData = calculateRealtime(range);
  
  // 3. 合并返回
  return [...cachedData, ...realtimeData];
}
```

#### 触发更新机制

| 触发条件 | 处理方式 |
|----------|----------|
| 交易新增/删除/修改 | 标记该日期之后数据为"脏数据"，异步重新计算 |
| 每日凌晨定时任务 | 计算前一天数据并落库 |
| 手动刷新 | 强制重新计算指定日期范围 |

#### 优化策略

| 策略 | 说明 |
|------|------|
| 增量更新 | 只重新计算受影响日期之后的数据 |
| 快照机制 | 每月初保存快照，作为重新计算的起点 |
| 脏数据标记 | 标记需要更新的数据，异步处理 |
| 分区存储 | 按年月分表，减少单表数据量 |

#### 未登录用户处理

- 系统每日自动记录上证指数（公共数据）
- 个人收益数据不需要登录也会计算记录
- 未登录用户可以看到上证指数曲线，也可看到当日的个人收益

#### 数据一致性

| 场景 | 处理方式 |
|------|----------|
| 交易数据变更 | 触发收益数据重新计算 |
| 外部 API 失败 | 标记为缺失，保留日志，用户可手动追溯 |
| 计算错误 | 记录日志，使用兜底值 |

#### 参考设计

参考支付宝理财和微信理财的设计：
- 实时估算收益
- 多维度对比（上证指数、沪深300等）
- 时间维度切换（日、周、月、季、年、成立以来）
- 累计收益率 + 年化收益率
- 收益来源分析
- 最大回撤、波动率等风险指标
- 交易记录与收益关联
- 盈亏日历热力图
- 目标收益/止损提醒
- 资产分布饼图

#### 营收日历

| 维度 | 内容 |
|------|------|
| 每日 | 盈亏金额、累计盈亏 |
| 每月 | 盈利天数、亏损天数、胜率、月度总盈亏金额、月度总收益率 |

## 6. 接口需求（前端依赖清单）

### 6.1 必需接口

- `POST /api/auth/login`
- `GET /api/assets/summary`
- `GET /api/trades/holdings`（需包含 currentPrice、dailyProfit、currency 等）
- `POST /api/trades`
- `PUT /api/trades/:id`
- `DELETE /api/trades/reviews/:id`（单笔删除）
- `DELETE /api/trades/holdings/:symbol`（整股删除）
- `GET /api/market/search`
- `GET /api/market/quote?symbol=...`
- `GET /api/market/overview`

### 6.2 关键数据约束

- `/api/market/quote` 必须对传入 symbol 严格校验，缺参返回 400
- 未授权返回 401（不要返回伪造的 symbol 或 0 价格对象）
- `/api/trades/holdings` 建议返回：
  - `currency`（CNY/HKD/USD）
  - `currentPrice`（原币种）
  - `dailyProfit`（原币种）
  - `profitRate`（百分比）

## 7. 非功能需求

### 7.1 性能

- 资产页加载：核心数据（资产概览+持仓）优先展示
- 行情轮询建议：30\~60 秒（避免限流）

### 7.2 安全

- 所有交易与资产接口必须鉴权
- token 存储与传输符合安全实践（不记录在日志中）

### 7.3 可用性

- 接口异常时需明确提示：
  - 行情获取失败、持仓获取失败、保存失败
- 删除类操作必须二次确认

***

## 8. 风险与待办（产品层面）

- **鉴权失败返回异常结构**会导致前端误以为是股票数据（如 symbol 为 `sys_auth`），需后端统一返回 401/403。
- **股票代码格式不统一**（如 `00700.HK` vs `HK00700`）会导致行情接口查不到数据，建议定义统一规范并在后端兼容。
